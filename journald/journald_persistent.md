# Практикум: налаштування постійного зберігання логів journald (systemd journal)

## Проблема

За замовчуванням на багатьох системах journald зберігає логи тільки в оперативній пам'яті (`/run/log/journal`). При перезавантаженні сервера всі логи зникають — неможливо відслідкувати причину перезавантаження чи збою.

## Рішення

Вмикаємо persistent-режим зберігання журналу з лімітами на розмір, щоб логи не з'їли весь диск.

Найчистіший підхід — створити окремий файл-фрагмент в `/etc/systemd/journald.conf.d/` замість редагування основного файлу `/etc/systemd/journald.conf`. Це дозволяє легко видалити наші налаштування, не чіпаючи основний конфіг, і вони переживуть оновлення пакета systemd.

## Кроки

Що робить: створює папку для фрагментів конфігурації, якщо не існує. Не впливає на роботу сервісів.

```bash
sudo mkdir -p /etc/systemd/journald.conf.d/
```

Що робить: створює окремий файл з нашими налаштуваннями. Не впливає на роботу сервісів.

```bash
sudo tee /etc/systemd/journald.conf.d/persistent.conf << 'EOF'
[Journal]
Storage=persistent
SystemMaxUse=500M
SystemKeepFree=1G
EOF
```

Пояснення параметрів:

- `Storage=persistent` — зберігати журнал на диску в `/var/log/journal` (папка створюється автоматично).
- `SystemMaxUse=500M` — журнал займе не більше 500 МБ.
- `SystemKeepFree=1G` — journald завжди залишить щонайменше 1 ГБ вільного місця на розділі.

Що робить: перезапускає journald, щоб підхопив нові налаштування. Не впливає на роботу сервісів.

```bash
sudo systemctl restart systemd-journald
```

Що робить: перевіряємо, що папка для журналів створилась. Тільки читає.

```bash
ls -ld /var/log/journal
```

## Перевірка

Що робить: показує, скільки місця займає журнал і чи працює persistent-режим (шлях має бути `/var/log/journal`, а не `/run/log/journal`). Тільки читає.

```bash
sudo journalctl --disk-usage
```

## Використання

Тепер після наступного перезавантаження (якщо воно відбудеться) можна подивитись останні записи попереднього завантаження — саме там зазвичай видно причину:

```bash
sudo journalctl -b -1 --no-pager | tail -50
```

Список усіх збережених завантажень:

```bash
sudo journalctl --list-boots
```

## Регулярне обслуговування

Перевіряти раз на тиждень, що журнал не розрісся:

```bash
sudo journalctl --disk-usage
```

## Відкат

Якщо треба повернути все як було — видаляємо наш фрагмент і перезапускаємо journald:

```bash
sudo rm /etc/systemd/journald.conf.d/persistent.conf
sudo systemctl restart systemd-journald
```
