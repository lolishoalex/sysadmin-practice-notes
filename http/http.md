# HTTP — практикум

**Тема:** протокол HTTP, заголовки, кешування, діагностика
**Стек:** nginx, WordPress (PHP-FPM + FastCGI cache), CDN/reverse-proxy рівня Cloudflare, TLS, curl, bash (awk/grep/sed/cut), логи доступу
**Формат:** робота на живому сайті, усі операції — тільки читання

---

## 1. Основи протоколу

Текстовий діалог: клієнт шле **запит**, сервер віддає **відповідь**.

```
GET /path/ HTTP/1.1          ← метод, шлях, версія
Host: example.com            ← вибирає сайт із багатьох на одному IP
User-Agent: curl/8.x
Accept: */*
                             ← порожній рядок = кінець заголовків
```

```
HTTP/1.1 200 OK
Server: nginx                     ← без версії = server_tokens off
Date: ...  GMT                    ← завжди GMT
Content-Type: text/html; charset=UTF-8
Transfer-Encoding: chunked        ← динамічна сторінка
Connection: keep-alive
Vary: Accept-Encoding
```

Розібрано:

- склад запиту впливає на відповідь (браузер шле ~15 заголовків, curl — три)
- `Date` завжди в GMT — розбіжність із локальним TZ сервера не є збоєм
- шлях у запиті ≠ шлях на диску (мовні префікси, rewrite)
- регістр назв заголовків: у HTTP/2 обов'язково малими, у HTTP/1.1 вільний

## 2. Статус-коди

| Код             | Значення                                                  |
| --------------- | --------------------------------------------------------- |
| 200             | OK                                                        |
| 301             | постійний редирект (`Location`)                           |
| 304             | Not Modified, тіла немає                                  |
| 400 / 403 / 404 | помилки клієнта                                           |
| 444             | не HTTP, директива nginx: закрити з'єднання без відповіді |
| 5xx-коди CDN    | генерує проксі, не origin                                 |

Класи: 2xx успіх, 3xx редирект, 4xx клієнт, 5xx сервер.

## 3. Безпекові заголовки

Опрацьовано призначення та коректні значення:

- `Strict-Transport-Security` — браузер сам переписує http→https без запиту; `max-age`, `includeSubDomains`, `preload` (вихід зі списку — місяці)
- `X-Frame-Options` — захист від clickjacking
- `X-Content-Type-Options: nosniff` — заборона вгадувати тип файлу
- `Referrer-Policy` — сучасне значення `strict-origin-when-cross-origin`
- `Permissions-Policy` — камера, мікрофон, геолокація, fullscreen; синтаксис `feature=()`
- `Content-Security-Policy` — найпотужніший, впроваджувати лише через `-report-only`
- `X-XSS-Protection` — мертвий заголовок, вилучений з браузерів, не використовувати

**Практичний висновок:** частину заголовків може додавати CDN, а не origin. При переході на прямий трафік вони зникають — тому задавати їх у nginx.

## 4. Команди (тільки читання)

```bash
# повний HTTP-діалог
curl -v https://example.com/ -o /dev/null

# заголовки справжнім GET (а не HEAD)
curl -s -o /dev/null -D - https://example.com/

# ланцюжок редиректів
curl -sIL http://example.com/ | grep -E "HTTP/|[Ll]ocation:"

# звернення до конкретного сервера повз DNS
curl -s -o /dev/null -D - --resolve example.com:443:203.0.113.10 https://example.com/

# узгодження стиснення
curl -s -o /dev/null -D - -H "Accept-Encoding: gzip" https://example.com/ | grep -i content-encoding

# умовний запит → 304
LM=$(curl -s -o /dev/null -D - "$URL" | grep -i "^last-modified:" | sed 's/^[^:]*: //' | tr -d '\r')
curl -s -o /dev/null -D - -H "If-Modified-Since: $LM" "$URL" | head -1

# аудит назв заголовків на помилки
curl -s -o /dev/null -D - https://example.com/ | cut -d: -f1 | sort

# статистика статус-кодів з логів (без IP)
sudo awk '{print $9}' /path/to/access.log | sort | uniq -c | sort -rn | head
```

## 5. Кеш

| Значення             | Що сталося                                     |
| -------------------- | ---------------------------------------------- |
| `HIT`                | віддано з кешу, PHP не запускався              |
| `MISS`               | згенеровано і закешовано                       |
| `EXPIRED`            | копія протухла, згенеровано заново             |
| `BYPASS`             | кеш обійдено (залогінений юзер або метод HEAD) |
| `DYNAMIC`            | не підпадає під кешування                      |
| `STALE` / `UPDATING` | віддано протухлу копію під час оновлення       |

Тривожний сигнал: `HIT` на адмінці, preview або `/.well-known/acme-challenge/`.

## 6. Пастки (головне з практики)

1. `/etc/hosts` на сервері може перехоплювати домен → локальний `curl` показує origin, а не публічну картину. Публічні перевірки — із зовнішньої машини.
2. **HEAD ≠ GET**: `curl -I` дає `BYPASS` на кеші. Для діагностики — `curl -s -o /dev/null -D -`.
3. Спершу статус-код, потім заголовки: редирект віддає мінімум заголовків.
4. Порожній вивід із `-D -` = немає відповіді взагалі (`return 444`), це не «200 з порожнім тілом».
5. `localhost` ≠ `127.0.0.1` (IPv6 `::1`) — адресу писати явно.
6. Заголовок з помилкою в назві = заголовка немає. Перевіряти по MDN.
7. Атрибути HTML-елемента перебивають заголовки документа (`referrerpolicy`).
8. `allow` на iframe делегує, але не створює дозвіл: порожній allowlist не обійти.
9. `add_header` у nginx **не накопичується** між рівнями — свій `add_header` у location скасовує успадковані.
10. Решта директив nginx навпаки успадковується: закомментований рядок ≠ вимкнено.
11. `nginx -t` не ловить семантику (зайва двокрапка в `add_header` валідна, заголовок не працює).
12. Конфіг показує намір, поведінка — факт: прочитав → гіпотеза → перевірив запитом → висновок.
13. Порожня змінна в `--resolve` тихо ігнорується.
14. `curl` не потребує `sudo`; root — лише для логів і `nginx -T`.
15. При перенесенні файлів зберігати mtime (`rsync -a`, `cp -a`), інакше `Last-Modified` скидається і всі клієнтські кеші протухають одночасно.

## 7. Гігієна даних під час діагностики

| Дані                                                        | Показувати                                            |
| ----------------------------------------------------------- | ----------------------------------------------------- |
| Вивід `curl -v` / `-D -`, статус-коди, дані TLS-сертифіката | ✅ публічне                                           |
| Конфіги nginx                                               | ✅ переважно, прибравши шляхи автентифікації й токени |
| Файли конфігурації CMS із паролями та солями                | ❌ ніколи                                             |
| Приховані адмін-шляхи                                       | ❌ ніколи                                             |
| `access.log` з IP відвідувачів                              | ❌ персональні дані (GDPR), тільки агрегати           |
| `set-cookie` з реальними значеннями                         | ❌ токени сесії                                       |
| API-токени CDN/DNS                                          | ❌ ніколи                                             |
